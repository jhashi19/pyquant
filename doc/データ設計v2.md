### 0. 設計規約
- すべての日時は UTCテキスト（`YYYY-MM-DD` 等）。市場の暦日解釈は `calendar_def.time_zone` で行う。
- 数値は SQLite の REAL。
- 列挙は CHECK で固定。参照整合は FK を付与。
- 監査列は原則 `created_at`。追記主義で上書きを避ける。
- 市場日付の決定や T+N 起算では TZ とカレンダーを用いる。年率時間は 日数計算で扱う。

### 1.参照データ
#### 1.1 `currency`（通貨マスタ）

##### 説明（テーブル）
表示・丸め規則、FXスポット既定ラグ、通貨既定カレンダーを保持。期日計算や表示、換算の基底情報。<br>
表示の原則：識別と計算は常に ccy（ISO）。人間向け表示で name／symbol を用途分け。
| 列名             | 型                | 必須 | 説明                |
| -------------- | ---------------- | -- | ---------------------------------------- |
| `ccy`            | TEXT (PK)        | Y  | ISO4217 3文字。全テーブルの通貨FKに使用。集計の軸。例：`'JPY'`、`'USD'`。                                               |
| `name`           | TEXT             | Y  | 通貨の正式名称（ローカライズ可）。UIのリストやラベルで使用。例：`'Japanese Yen'` / `'円'`、`'US Dollar'` / `'米ドル'`。              |
| `iso_numeric`    | INTEGER (UNIQUE) |    | 外部ベンダーやCSV連携時の同定キー。例：JPY=`392`、USD=`840`。                                                           |
| `minor_unit`     | INTEGER          | Y  | 金額表示の丸め桁。UI/帳票のフォーマッタで使用。例：JPY=`0`、USD=`2`。                                                         |
| `symbol`         | TEXT             |    | 金額の書式用記号。単一通貨画面で使用。例：JPY=`'¥'`（`'￥'`もあり）、USD=`'$'`。 |
| `spot_lag`       | INTEGER          | Y  | FXスポット決済ラグ営業日（デフォルト=`2`）。T+N起算に使用。                                                                   |
| `default_cal_id` | TEXT             |    | 既定の営業日カレンダー。取引でカレンダー未指定時のフォールバック。決済日の営業日調整に使用。                                |
| `enabled`        | INTEGER          | Y  | 論理有効フラグ。廃止通貨を物理削除せずに非表示化。履歴と参照整合を維持。               |
| `valid_from`     | TEXT             | Y  | 通貨定義の適用開始。`minor_unit`や`spot_lag`変更の有効時点を明示。履歴管理。                                 |
| `retired_at`     | TEXT             |    | 廃止日。新規計上や取込時のバリデーションに使用（期間オーバーを即検知）。                                     |
| `created_at`     | TEXT             | Y  | 監査用タイムスタンプ（UTC）。                                         |
##### 使用例
- 通貨選択UI：name を「US Dollar (USD)」「円 (JPY)」の形で表示。
- 残高画面（JPYのみ）：symbol='¥' を前置し ¥1,234,567 と表示。複数通貨明細では USD 1,234.56 / JPY 150,000 のように ccy を優先。
- スポット日計算：spot_lag=2 を使って T+2 を算出。
- 取引でカレンダー未指定：default_cal_id を参照。

#### 1.2 `currency_calendar`（通貨とカレンダーの紐付け）
##### 説明（テーブル）
通貨に対し、既定・決済・休日専用など役割別の市場カレンダーを割り当てる。
| 列名     | 型                  | 必須 | 説明                             |
| ------ | ------------------ | -- | ---------------------------------------------------------- |
| `ccy`    | TEXT (FK→currency) | Y  | 対象通貨を指定。                                   |
| `cal_id` | TEXT               | Y  | 使用する市場カレンダーID。休日集合を表す識別子（`calendar.cal_id`）。<br>例：`'USNY'`（米国NY市場）, `'JPTO'`（日本東京市場）。<br>補足：SQLiteは複合主キーの部分参照にFK制約を張れないため、この列は実質的にドメイン制約。            |
| `role`   | TEXT (CHECK)       | Y  | カレンダーの用途区分。1通貨に複数のカレンダーを役割別に持てる。<br>`DEFAULT`=取引・カーブでカレンダー未指定時の既定。期日生成や営業日調整の初期値。<br>`SETTLEMENT`=FXスポットラグなど決済日の営業日調整に用いる基準。<br>`HOLIDAY_ONLY`=休日集合としての参照用途。単独で営業日調整に使わない想定。<br>roleを増やすならCHECKを拡張（例：`'FIXING'`, `'PAYMENT'` など）か、roleを別テーブルで管理。  |
##### 使用例
- FX決済の共通営業日判定で、両通貨の SETTLEMENT をAND判定。
- レグの支払カレンダー未指定時、DEFAULT をフォールバック。

##### 説明（テーブル）
年率化規約を識別。PVの割引時間やクーポン計算に使用。
| 列名           | 型             | 必須 | 説明               |
| ------------ | ------------- | -- | -------------------------- |
| `code`         | TEXT (PK)     | Y  | 人間・機械共通のキー。例: `ACT/360`, `ACT/365F`, `30E/360`, `ACT/ACT-ISDA`。 |
| `display_name` | TEXT          | Y  | 表示名。例: `Actual/365 Fixed`。                  |
| `formula_tag`  | TEXT (UNIQUE) | Y  | 実装を一意に決める識別子。例:`ACT_360`, `ACT_365F`, `ACT_365L`, `ACT_ACT_ISDA`, `ACT_ACT_ICMA`, `THIRTY_360_US`          |
| `notes`        | TEXT          |    | 例外や出典のメモ。  |
| `enabled`      | INTEGER       | Y  | 有効/無効の論理フラグ。   |
| `created_at`   | TEXT          | Y  | 監査用タイムスタンプ（UTC）。   |
##### 使用例
- `pricing_curve_def.daycount` としてゼロ金利の年率化、`ref_rate_rule.daycount` としてクーポン年率化を決定。

#### 1.4 `bizday_convention`（営業日規則）
##### 説明（テーブル）
非営業日をどう繰り延べるかのルール。期日生成・満期調整に使用。
| 列名                 | 型            | 必須 | 説明              |
| ------------------ | ------------ | -- | ------------------------- |
| `code`               | TEXT (PK)    | Y  | 例：`F`, `MF`, `P`。外部指定キー。<br>用途: 取引やスケジュール生成で指定する実運用キー。  |
| `display_name`       | TEXT         | Y  | 画面表示名。例: `Following`, `Preceding`, `Modified Following`, `Modified Preceding`, `Nearest`。                     |
| `rule_tag`           | TEXT (CHECK) | Y  | 実装の分岐。期日調整関数で直接使用。<br>例:`FOLLOWING`, `PRECEDING`,`MOD_FOLLOWING`（同月維持。次月に入るならPRECEDINGへ）, `MOD_PRECEDING`（同月維持。前月に入るならFOLLOWINGへ）, `NEAREST`（前後の近い営業日へ）, `NONE`（無調整）        |
| `nearest_tiebreaker` | TEXT (CHECK) |    | `rule_tag`：`NEAREST`専用。前後が同距離のときどちらを選ぶかの規則。デフォルト`NULL`＝実装既定。 |
| `notes`              | TEXT         |    | 規約メモ。                     |
| `enabled`            | INTEGER      | Y  | 有効/無効。廃止時に物理削除せず切替。   |
| `created_at`         | TEXT         | Y  | 監査用UTCタイムスタンプ。    |
##### 使用例
- IRSの支払日を MF で月内に繰り上げ。
- インデックスFixingを F で繰り延べ。

| `created_at`   | TEXT      | Y  | 監査用UTC。             |
##### 使用例

##### 説明（テーブル）
市場ごとの休場日と短縮取引日を保持。期日生成・締時刻で使用。

#### 1.7 `ref_rate_rule`（参照金利規則）
##### 説明（テーブル）
変動レグのFixing規約とO/N→期間化を定義。スワップやCap/Floor生成に必須。
| 列名                   | 型                  | 必須 | 説明             |
| -------------------- | ------------------ | -- | --------------------------------- |
| `ref_rate_id`          | TEXT (PK)          | Y  | 例：`'USD-SOFR'`,`'USD-SOFR-3M'`,`'JPY-TONAR'`。プログラムでレート情報と紐づけるためのキー。   |
| `ccy`                  | TEXT (FK→`currency.ccy`) | Y  | レートに対応する通貨。              |
| `tenor`                | TEXT               | Y  | レートのテナー。例：`'ON'`,`'1M'`,`'3M'`  |
| `daycount`             | TEXT (FK→`daycount.code`) | Y  | レートに対応する日数計算方式。             |
| `display_name`         | TEXT               | Y  | 表示名。UI・ログで誤認を避ける。例: `“USD SOFR 3M Term”`。   |
| `index_family`         | TEXT               | Y  | 系統ラベル。例: `SOFR`, `TONAR`, `LIBOR`。監査や検索で便利。 |
| `rate_type`            | TEXT (CHECK)       | Y  | O/N参照か期間物か。`'ON'`=翌日物（SOFR, TONAR）、`'TERM'`=1M/3M等のタームレート。レグの生成で分岐。    |
| `fixing_cal_id`        | TEXT (FK→`calendar_def.cal_id`)  | Y  | Fixing判定に使う市場カレンダーID。例: `USNY`, `JPTO`。指数の「観測日」はこのカレンダーで決まる。 |
| `fixing_bdc`           | TEXT (FK→`bizday_convention.code`)   | Y  | Fixing日の営業日調整（`F`/`MF`等）。指数の「観測日繰上げ/繰下げ」を明示。   |
| `fixing_time_local`    | TEXT               |    | ローカル時刻の締切。将来の締切ロジックや半休対応の拡張点（v1は保存のみ）。例: `'08:00'`。      |
| `fixing_tz`            | TEXT               |    | Fixingローカル日の決定。デフォルトのタイムゾーンは`calendar_def.time_zone`を使用する。実装では`COALESCE(ref_rate_rule.fixing_tz, calendar_def.time_zone)`として取得するイメージ。                   |
| `publication_lag_days` | INTEGER            | Y  | 公表遅延。SOFRは通常T+1など。EOD計測やバッチの依存順序に使用。    |
| `accrual_conv`         | TEXT (CHECK)       | Y  | O/Nを期間化する計算方法。<br>`SIMPLE`: 日割単利合成<br>`COMPOUND_IN_ARREARS`: 後決め複利（OISクーポン）<br>`AVERAGE`: 単純平均（公表平均を使う場合）<br>`TERM_QUOTE`: 期間物タームレート（1M/3M等）をそのまま使用 |
| `lookback_days`        | INTEGER            | Y  | 後決めでのルックバック（例: 5D lookback=`5`）。将来のOIS詳細に備える。v1は`0`。  |
| `lockout_days`         | INTEGER            | Y  | ロックアウト日数（期末数日を一定レート固定）。v1は`0`。 |
| `source_tag`           | TEXT               |    | データ取得元ベンダー。例：`bbg`, `reuters`, `manual` |
| `enabled`              | INTEGER            | Y  | 有効/無効。廃止時に物理削除せず切替。     |
| `valid_from`           | TEXT               | Y  | マスタ適用開始日。           |
| `retired_at`           | TEXT               |    | 廃止日。              |
| `created_at`           | TEXT               | Y  | 監査UTC。               |
##### 使用例
- USD-SOFR の OIS クーポン期間化で COMPOUND_IN_ARREARS を選択。
- Fixing日生成で `fixing_cal_id` と `fixing_bdc` を適用。

#### 2.1 `market_snapshot`（評価時の入力値のスナップショット）
##### 説明（テーブル）
評価で参照するマーケット入力の“版”を一意に識別する。取込ソース、ローダのバージョン、データ同一性ハッシュ、承認・凍結情報を保持し、再現性と監査を担保する。
| 列名                   | 型                                           |  必須 | 説明（使用場面）                                      |
| -------------------- | ------------------------------------------- | :-: | --------------------------------------------- |
| `snapshot_id`        | TEXT（PK）                                    |  Y  | 版ID。全マーケット表や `run.snapshot_id` の参照先。          |
| `as_of`              | TEXT（`YYYY-MM-DD`）                          |  Y  | 論理市場日。EOD/カット選別の主キー軸。                         |
| `as_of_tz`           | TEXT（IANA TZ）                               |  Y  | 市場日の解釈TZ。例：`Asia/Tokyo`。                      |
| `cut_label`          | TEXT                                        |     | 運用カット名。`'EOD'`, `'NY_10AM'`, `'LDN_4PM'` など。  |              |
| `data_hash`          | TEXT（UNIQUE）                                |  Y  | 入力一式の総ハッシュ。重複取込防止と完全同一性確認。                    |
| `parent_snapshot_id` | TEXT（FK→`market_snapshot.snapshot_id`）                  |     | 親版。差分・派生の系譜管理。                                |
| `is_locked`          | INTEGER（`0`/`1`）                                |  Y  | `1`=ロック済。評価参照はロックのみを原則化。                        |
| `qa_status`          | TEXT（CHECK：`PENDING`/`APPROVED`/`REJECTED`） |     | 品質審査状態。本番利用ガードに使用。                            |                             |
| `note`               | TEXT                                        |     | 補足（臨時休場・欠測補完、qa_status：REJECTの場合の理由など）。                              |
| `freeze_time_utc`    | TEXT（UTC）                                   |     | 版を凍結した実瞬間。最新確定選定に利用。                          |
| `created_at`         | TEXT（UTC）                                   |  Y  | 生成時刻。監査用。                                     |
| `updated_at`         | TEXT（UTC）                                   |  Y  | 更新時刻。監査用。                                     |
##### 使用フロー
1. ロード → market_snapshot 挿入（`data_hash` 算出、`as_of`/`as_of_tz`/`cut_label`/`src_tag`/`loader_version` を記録）。
1. 同 snapshot_id で fx_spot、curve_point、vol_*、model_param を投入。
1. 検証・承認 → qa_status='APPROVED'、freeze_time_utc 設定 → is_locked=1。
1. 評価 → run.snapshot_id に指定。以後は不変参照。

#### 2.2 `fx_spot`（為替スポットレート）
##### 説明（テーブル）
スナップショット時点の為替スポットを保持する。
評価の換算（PV通貨変換）、CIP（カバード金利平価）計算、将来の約定コスト見積（bid/ask）やクロス導出の監査に用いる。snapshot_id ごとに不変。
| 列名  | 型  |  必須 | 説明    |
| ----- | --- | --- | ---------------- | 
| `snapshot_id`      | TEXT（FK→`market_snapshot.snapshot_id`） |  Y  | どの版のレートかを識別。評価では `run.snapshot_id` と一致させて再現性を担保。                       |
| `base_ccy`         | TEXT（FK→`currency.ccy`）        |  Y  | レートの分子通貨。集計・JOINの主キー軸。例：`'USD'`。     |
| `quote_ccy`        | TEXT（FK→`currency.ccy`）        |  Y  | レートの分母通貨。例：`'JPY'`。  |
| `pair`             | TEXT                       |  Y  | ヒューマン可読のペア文字列。       |  
| `spot`             | REAL                       |  Y  | MIDレート。`bid/ask` がある場合は `(bid+ask)/2` をアプリでセット。PV換算やCIPの基準に用いる。    |
| `bid`              | REAL                       |     | 片サイド。`ask` と併用し約定コスト・スプレッド評価に使用。`bid <= ask` を CHECK。             |
| `ask`              | REAL                       |     | 片サイド。上記同様。      |
| `quote_time_utc`   | TEXT（UTC）                  |     | このペアの観測タイムスタンプ。同一スナップショット内での鮮度差や遅延解析に使用（`market_snapshot.freeze_time_utc` は版の確定瞬間、こちらは銘柄個別）。 |
| `source_symbol`    | TEXT                       |     | ベンダの**ティッカー/銘柄ID**。障害時のトレースやベンダ仕様差の切り分けに使用。      |
| `is_cross_derived` | INTEGER（`0`/`1`）               |  Y  | `1`=クロス導出（例：`EURJPY = EURUSD × USDJPY`）。直物が無い通貨ペアの監査に有用。     |
| `derived_via_1`    | TEXT                       |     | クロス導出の由来ペア1。`is_cross_derived`=`1` のとき必   |
| `derived_via_2`    | TEXT                       |     | クロス導出の由来ペア2。`is_cross_derived`=`1` のとき必須。                 |
##### 使用例
- 評価時に使用する為替レートは対象の`pair`のレコードの`spot`
- `is_cross_derived`=`1` の行は、`derived_via_1`・`derived_via_2` を辿って再計算検証が可能。
