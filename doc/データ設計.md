### 0. 設計規約
- すべての日時は UTCテキスト（`YYYY-MM-DD` 等）。市場のカレンダーの解釈は `calendar_def.time_zone` で行う。
- 数値は SQLite の REAL。
- 参照整合は FK を付与。取引追加や計算ロジック・アルゴリズム追加時にデータ・レコードの追加が必要になるようなものは別途マスタテーブルを作成し、FK を付与。固定で追加が発生しないようなものについては CHECK で挿入時に確認する。
- 監査・各種分析用に `created_at`でデータ挿入時刻を保持。追記主義で上書きを避ける。
- 市場日付の決定や T+N 起算では TZ とカレンダーを用いる。

### 1.参照データ
#### 1.1 `currency`（通貨マスタ）

##### 説明
通貨の定義、および表示・丸め規則、FXスポット既定ラグなど通貨固有の情報を保持する。
| 列名             | 型                | 必須 | 説明                |
| -------------- | ---------------- | -- | ---------------------------------------- |
| `ccy`            | TEXT (PK)        | Y  | ISO4217 アルファベット3文字。全テーブルの通貨FKに使用。例：`JPY`, `USD`。|
| `name`           | TEXT             | Y  | 通貨の正式名称（英語 / 日本語）。UIのリストやラベルで使用。例：`Japanese Yen / 円`、`US Dollar / アメリカ合衆国ドル`。              |
| `iso_numeric`    | TEXT (UNIQUE) |    | ISO4217 数字3桁。外部ベンダーやCSV連携時の同定キー。例：JPY=`392`、USD=`840`。                                                           |
| `minor_unit`     | INTEGER          | Y  | ISO4217 数字1桁。金額表示の丸め桁。例：JPY=`0`、USD=`2`。  |
| `symbol`         | TEXT             |    | 金額の書式用記号。単一通貨画面で使用。例：JPY=`'¥'`（`'￥'`もあり）、USD=`'$'`。 |
| `spot_lag`       | INTEGER          | Y  | FXスポット決済ラグ営業日（デフォルト=`2`）。T+N起算に使用。   |
| `enabled`        | INTEGER（CHECK=`0`/`1`）| Y  | 論理有効フラグ。廃止通貨を物理削除せずに非表示化。有効=`1`, 無効=`0`。|
| `valid_from`     | TEXT             | Y  | 通貨定義の適用開始。`minor_unit`や`spot_lag`などの変更の有効時点を明示。|
| `retired_at`     | TEXT             |    | 廃止日。新規計上や取込時のバリデーションに使用（期間オーバーを即検知）。 |
| `created_at`     | TEXT             | Y  | 登録タイムスタンプ（UTC）。              |
##### 使用目的
- 取引通貨など、システム内で使用する通貨はすべてこのテーブルにあるものを使用する。
- 各通貨の表示やスポットラグなど、通貨ごとのメタデータもカラムとして持ち、システム内のUIや計算で使用する。

#### 1.2 `currency_calendar`（通貨カレンダー定義）
##### 説明
通貨に対し、既定・決済・休日専用など役割別の市場カレンダーを割り当てる。<br>
複合キー：ccy, role
| 列名     | 型                  | 必須 | 説明                             |
| ------ | ------------------ | -- | ---------------------------------------------------------- |
| `ccy`    | TEXT (FK→currency) | Y  | 通貨。                                   |
| `role`   | TEXT (CHECK)       | Y  | カレンダーの用途区分。1通貨に複数のカレンダーを役割別に持てる。取引やカーブでカレンダーが指定されている場合はその指定を優先。無い場合に以下を使用。<br>`EXCHANGE`=上場ものの場合に使用。<br>`SETTLEMENT`=FX系の 受渡/スポット/行使 に使用。<br>`DEFAULT`=FX系でない場合に使用。<br>`HOLIDAY_ONLY`=休日集合としての参照用途。単独で営業日調整に使わない想定。<br>将来 `FIXING`/`CLEARING` など追加可能。  |
| `cal_id` | TEXT               | Y  | 使用する市場カレンダーID。休日集合を表す識別子（`calendar.cal_id`）。<br>例：`USNY`（米国NY市場）, `JPTO`（日本東京市場）。<br>補足：SQLiteは複合主キーの部分参照にFK制約を張れないため、この列は実質的にドメイン制約。            |
| `enabled`        | INTEGER（CHECK=`0`/`1`）| Y  | 論理有効フラグ。有効=`1`, 無効=`0`。|
| `created_at` | TEXT         |  Y  | 登録タイムスタンプ。        |
##### 使用目的
- 通貨とカレンダー（休日集合）を紐づける。

#### 2.1 `market_snapshot`（マーケットデータスナップショット）

評価で参照するマーケット入力の“版”を一意に識別する。取込ソース、ローダのバージョン、データ同一性ハッシュ、承認・凍結情報を保持し、再現性と監査を担保する。
| 列名                   | 型                             |  必須 | 説明　　　      |
| -------------------- | ------------------------------- | :-: | ------------------------------------------- |
| `snapshot_id`        | TEXT（PK）              |  Y  | 版ID。全マーケット表や `run.snapshot_id` の参照先。  |
| `as_of`              | TEXT（`YYYY-MM-DD`）    |  Y  | 論理市場日。EOD/カット選別の主キー軸。        |
| `as_of_tz`           | TEXT（IANA TZ）         |  Y  | 市場日の解釈TZ。例：`Asia/Tokyo`。               |
| `cut_label`          | TEXT                    |     | 運用カット名。`EOD`, `NY_10AM`, `LDN_4PM` など。  |
| `data_hash`          | TEXT（UNIQUE）          |  Y  | 入力一式の総ハッシュ。重複取込防止と完全同一性確認。  |
| `parent_snapshot_id` | TEXT（FK→`market_snapshot.snapshot_id`）   |     | 親版。差分・派生の系譜管理。  |
| `is_locked`          | INTEGER（`0`/`1`）      |  Y  | `1`=ロック済。評価参照はロックのみ。         |
| `qa_status`          | TEXT（CHECK：`PENDING`/`APPROVED`/`REJECTED`） |     | 品質審査状態。本番利用ガードに使用。 |
| `note`               | TEXT                  |     | 補足（臨時休場・欠測補完、qa_status：REJECTの場合の理由など）。|
| `locked_at`          | TEXT（UTC）             |     | 版をロックした時刻。最新確定選定に利用。       |
| `created_at`         | TEXT（UTC）             |  Y  | 登録タイムスタンプ（UTC）。    |
##### 使用目的
- システム内で評価時に使用するマーケットはこのテーブルのレコードに紐づく。
- このテーブルのsnapshot_idに紐づくほかのマーケットデータ（テーブル）のレートを使用して計算する。

#### 2.8 `market_bond_price`（債券市場価格）
##### 説明

スナップショット時点の債券市場価格（クォート）を保持するテーブル。
market_snapshot.snapshot_id と bond_def.security_id の組み合わせで「いつの・どの銘柄の価格か」を一意に識別する。
クリーン価格・ダーティ価格・到来利回り（yield to maturity）・bid/ask など、ベンダから取得した価格情報を保持し、以下に使用する。
- 債券 PV 計算時の市場価格として利用（理論価格との比較、スプレッド推定）。
- BOND カーブ（pricing_curve_def.curve_type='BOND'）ブートストラップのインプット。

| 列名              | 型                                      |  必須 | 説明                   |
| --------------- | -------------------------------------- | :-: | --------------------------------- |
| `snapshot_id`   | TEXT（FK→`market_snapshot.snapshot_id`） |  Y  | どのマーケット版の価格かを識別するキー。評価では `run.snapshot_id` と一致させ、同じスナップショット内の `curve_point` や `fx_spot` 等と整合を取る。       |
| `security_id`   | TEXT（FK→`bond_def.security_id`）        |  Y  | どの債券銘柄かを識別するキー。`bond_def` からクーポン・満期・通貨などの条件を取得し、PV 計算や利回り→価格変換に用いる。              |
| `clean_price`   | REAL                                   |     | クリーン価格（通常、額面100に対する百分率、例：`99.75`）。クーポンの経過利子分を除いた価格。ベンダがクリーンで配信している場合に格納。ダーティ価格が無い場合は、ここと `bond_def` の条件からダーティ価格を算出してもよい。                |
| `dirty_price`   | REAL                                   |     | ダーティ価格（経過利子込みの価格、同じく % of par 想定）。キャッシュフローの割引結果と直接比較する際に使用。クリーン価格しか無い場合は、評価ロジック側で算出し、この列を NULL のままでもよい。                                 |
| `yield_to_mty`  | REAL                                   |     | 到来利回り（Yield to Maturity）。年率実数（例：`0.0123` = 1.23%）を想定。ローカル市場慣行（複利/単利・支払頻度）に従う前提で、債券価格と利回りの相互変換に使用。`bond_def` のクーポン規約と組み合わせて価格を再構成可能。     |
| `bid`           | REAL                                   |     | Bid 価格（買気配）。`clean_price`/`dirty_price` が MID の場合、`(bid, ask)` と合わせてスプレッド評価・約定コスト評価に使用できる。NULL の場合は片サイド欠損。                              |
| `ask`           | REAL                                   |     | Ask 価格（売気配）。`bid` と合わせ、`bid <= ask` となるように取込ロジックで検証することが望ましい。板スプレッドやリクイディティ評価の材料にもなる。                                                   |
| `quote_ccy`     | TEXT（FK→`currency.ccy`）                |     | 価格のクォート通貨。通常は `bond_def.ccy` と同一だが、ユーロボンドなどで異通貨クォートを扱う場合に使用（例：EUR 建て債を USD 価格でクォート）。NULL の場合は「券面通貨と同じ」とみなす運用も可能。                        |
| `source_symbol` | TEXT                                   |     | ベンダティッカー/銘柄コード。障害時のトレース、データ差異（ベンダ A/B）の切り分けなどに使用。例：Bloomberg Ticker、Reuters RIC 等。                                                      |
| `frozen_at`     | TEXT                                   |     | 当該銘柄価格の観測 UTC 時刻。`market_snapshot.as_of` と別に、「実際にベンダから取得したタイムスタンプ」を持つことで、カット時間内での微妙な差（ロール直前/後など）を追跡できる。空欄でもよいが、将来の QA や再現性向上のため保持が望ましい。 |
